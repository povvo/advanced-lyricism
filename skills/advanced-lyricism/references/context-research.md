# Context and Scene Research — Deep Reference

> Working template: `assets/templates/context-research.md`
> Machine routes: `assets/domain-registry.json` · `assets/tool-catalog.json` · `assets/dependency-manifest.json` · runtime method `references/runtime-orchestration.md`
> This reference contains the domain method; its paired template carries the method through active lyric work.

## 1. Composition role

This layer supplies current artist, scene, production, language and platform context wherever freshness affects the lyric.

- It receives the research question, time/place boundary, supplied references and the exact craft decision at stake.
- It produces dated observations, usable language/context constraints and clearly labelled priors for concept, voice, genre, narrative and lexical work.
- The paired template keeps source observations separate from interpretation and creative application.

## 2. Core craft model

Use this domain to connect current artist, scene, slang, production, and platform context to lyric craft decisions.

## Separate input types
- craft observations: what happens in lines/performance;
- scene signals: relationships, language and production circulating now;
- platform signals: search/recommendation/engagement surfaces;
- user preference: what this writer wants.

Popularity cannot prove lyric quality.

## Artist reference -> properties
Translate an artist reference into concrete properties:
- vowel matching;
- cadence shape;
- landing behaviour;
- narrative density;
- deadpan vs melodic delivery;
- hook economy;
- local syntax;
- image/reference density.

## Input priority
Prefer:
1. user-supplied lyrics/audio;
2. actual beat;
3. primary artist material/interviews when research requested;
4. reliable linguistic/musicological sources;
5. multiple current scene signals;
6. autocomplete/platform analytics as weak behavioural signals.

## Scene graph
Map artists, producers, tracks, collaborations, collectives, localities, recurring terms and production patterns. Relations are more informative than a flat popularity list.

## Triangulate
For each current feature record observation, source type, date, confidence and craft implication. Do not force uncertain slang.

## MLE query translation
When a term is unfamiliar, research the usage context, pragmatic function and polysemy. Preserve user-supplied form unless the task requires correction.

## Audio/metadata reconciliation
Treat BPM/key/mood metadata as claims; compare with audible pulse/energy when tools permit and retain conflicts.

## Taste learning
From user choices update working preferences: density, reference tolerance, emotional distance, rhyme looseness, melodic space, register.

## Runtime boundary
Artist discovery, autocomplete, scene radar, recommendation surfaces, scene graphs, beat analysis, and taste models expand the research layer whenever their inputs and connections are available. Live services are volatile; their output supplies context rather than determining craft quality.

Record every task-relevant observation, relationship, contradiction, date, uncertainty, and craft implication in `assets/templates/context-research.md`.

## 3A. Current-context research protocol

### Decide whether research has value
Research current facts that can strengthen diction, reference choice, production fit, register, or interpretation.
Use the answer wherever it enriches diction, reference choice, scene context, production fit, register, interpretation, or later research; continue through every connected craft layer.

### Decompose the question
- What property is actually needed?
- Is it a durable craft pattern or a time-sensitive scene signal?
- Is the target an artist, producer, locality, collective, platform, release, or language feature?
- What date range is relevant?
- What would falsify the working assumption?

### Source hierarchy
1. user-supplied material and explicit preference;
2. primary material: official release/performance/interview/source;
3. current reputable reporting or direct technical documentation;
4. scholarly or linguistic work for durable mechanisms;
5. community reports for usage/reaction, labelled as such;
6. use search snippets and autocomplete as discovery clues, then connect them with direct sources, scene relationships, supplied material, and language context.

### Freshness
- Attach a date to time-sensitive observations.
- Distinguish release date, publication date, and the date the event occurred.
- Do not use a newly uploaded copy of an old document as proof of current practice.
- Prefer several recent observations before describing a scene-wide tendency.

### Artist-reference translation
Translate the reference into observable properties such as:
- vowel/stress matching;
- cadence footprint;
- line-ending behaviour;
- narrative density;
- deadpan versus melodic delivery;
- hook economy;
- local syntax;
- image/reference density;
- use of silence;
- section-level contrast.

### Language and slang verification
- Verify meaning in context before using an unfamiliar term.
- Separate lexical meaning from social relation and pragmatic force.
- Check whether a term is local, dated, ironic, reclaimed, or audience-specific.
- Prefer supplied user usage over generic scene assumptions.

### Contradiction handling
- Preserve conflicting source findings instead of silently averaging them.
- Record what each source actually supports.
- Prefer narrower claims when the scene is heterogeneous.
- Treat uncertainty as a routing signal, not a reason to guess.

### Research output
Every material observation should retain:
- source;
- date;
- observation/source type;
- confidence;
- exact craft implication;
- unresolved scope and verification questions.

Translate the result into a concrete craft implication before returning to lyric work. Do not return a bibliography, popularity digest, or source list unless the user explicitly asks for research reporting.

## 4. Decision method

### 4.1. Frame
- Name the section function, hard constraints, and the complete set of craft objectives and questions.
- Record the decision in `assets/templates/context-research.md`.

### 4.2. Baseline
- Describe the present behaviour before judging it.
- Record the decision in `assets/templates/context-research.md`.

### 4.3. Hinge
- Identify the full set of words, bars, events, and performance moments involved in the binding issue.
- Record the decision in `assets/templates/context-research.md`.

### 4.4. Mechanism
- Explain how the suspected variable creates the observed effect.
- Record the decision in `assets/templates/context-research.md`.

### 4.5. Isolate
- For causal comparison, hold strong dimensions fixed while varying each suspected lever separately; then combine every improvement that survives its isolated test.
- Record the decision in `assets/templates/context-research.md`.

### 4.6. Material and tool support
- Ground the decision in supplied creative material, direct reading or rehearsal, and every relevant representation, detector or generator.
- Record the decision in `assets/templates/context-research.md`.

### 4.7. Audition
- Compare baseline and candidate in the medium that matters.
- Record the decision in `assets/templates/context-research.md`.

### 4.8. Collateral
- Check meaning, voice, rhyme, rhythm, performance, sequence, and consequence as relevant.
- Record the decision in `assets/templates/context-research.md`.

### 4.9. Commit
- Keep the most effective change set that survives audition without analytical explanation.
- Record the decision in `assets/templates/context-research.md`.

### 4.10. Handoff
- Pass observations, locked decisions, open questions, and research outputs into every connected domain that can use them.
- Record the decision in `assets/templates/context-research.md`.

## 7. Script routes — preflight each listed tool with `python scripts/tool_router.py --tool <id>` before execution

### Primary
- `context_query_plan` → `scripts/context_query_plan.py`
  - Contribution: translates supplied language and research intent into ordered queries for the available research tools.
  - Class: `generation`.
- Execute every query route that can assist the lyric, using autocomplete and community variants for discovery and stronger sources for verification where available.
- `scene_graph` → `scripts/scene_graph.py`
  - Contribution: maps supplied artist/track/producer/locality relationships and explains bounded paths between nodes.
  - Class: `representation`.
- Keep relation type, date and source support visible; proximity is not quality or influence.
- `lexical_cloud` → `scripts/lexical_cloud.py`
  - Contribution: vocabulary concentration, motif frequency or revision delta.
  - Class: `detection`.

### Secondary
- `preference_profile` → `scripts/preference_profile.py`
  - Contribution: summarises feature directions and stated reasons across supplied keep/reject history.
  - Class: `detection`.
- Current instructions outrank historical associations; no profile is persisted automatically.

### Tool-class boundaries
- Representation keeps supplied material beside labelled derived structure.
- Detection maps concrete conditions and opportunities with locations and confidence.
- Generation and transformation create controlled candidates.
- Evaluation combines mechanical observations with close reading, audition and comparison.
- Support checks runtime/package state, not craft quality.

## 9. Failure modes

Repair the named craft variable, audition the result, and recheck every layer it changes.

### Popularity treated as quality

### One artist treated as whole scene

### Search snippets treated as proof

### Slang guessed from context

### Old scene information used as current

### Platform engagement inferred as craft merit

### User preference overwritten by trend

### Contradictory sources silently reconciled

### Current research performed when it cannot change the decision
